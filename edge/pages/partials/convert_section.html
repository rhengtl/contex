{# --------------------------------------------------------------------------- The conversion feature. There is only one. templates/partials/convert_section.html, carried across. Five input methods (file picker, drag-and-drop, .docx, camera, canvas) all set name="file" on one input. The user is never asked which engine reads their page, because that was always a question about our implementation rather than about their document. (.docx is off until its extraction path is ported -- see public/pages.js.) This file holds BOTH states of the workspace, because they are states and not stacked content: before a conversion you see the input panel, after one you see the document. The old layout kept the upload controls above the result, so the finished document - the thing you came back for - appeared below a control you had already used. Flask rendered one state per response and this renders both, hidden, for app.js to swap. That is the whole of the difference: the markup of each state, its classes and its order are the originals. Nothing here is usable until the terms checkbox is ticked; the gate is enforced again in the Worker on every /api/convert/page. --------------------------------------------------------------------------- #}
